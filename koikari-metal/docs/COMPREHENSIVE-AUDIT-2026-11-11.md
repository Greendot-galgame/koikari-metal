## 结论

本轮当时发现并修复了一批隐藏问题，不能把之前的测试通过理解为“没有 bug”。截至该日，下述覆盖范围内记录 **124 项测试全部通过**，所复现的剧情推进阻塞均已处理；这不是对其他资源版本或未来兼容性的保证。**真实资源测试不在普通 CI 中**：没有资源或没有启用相关开关时，部分测试提前返回，不能据“通过”数量推断资源覆盖。

检查采用源码交叉审查、合成坏输入复现、两种资源模式的无画面运行、存档往返与真实 Metal 像素回归。未展示敏感画面或进行媒体试听，未执行原始 TJS/DLL，也未读写用户已有存档。测试只在自己的临时目录中创建合成存档。

## 发现并修复的问题

| 类别 | 触发与风险 | 修复 |
|---|---|---|
| 标题页存档覆盖（高优先级） | 未开局时误按 F5，旧逻辑会成功写入空状态并覆盖进度 | 标题页或未开始时忽略保存，且不解析/访问存档路径；测试验证原文件字节不变 |
| 输入上下文 | 标题页 A/H/B 可提前改变自动、文本隐藏或进入空对话历史页；报错时自动/快进仍不断推进尝试 | 限制游戏内快捷键的上下文，VM 阻塞时暂停自动推进 |
| 错误回报（高优先级） | 开局、选项及加载返回 `Ok(Blocked)`，控制器可能清空错误，表现为卡住却无报错 | 合成器直接读取当前 VM 诊断，不会被存读档成功提示遮蔽；存储失败也可见 |
| 读档事务与依赖身份 | 拒绝坏档前已向程序缓存加入新脚本；回退旧档或重新开局后仍把无关缓存写入快存依赖 | 在候选运行时完整校验后才提交；执行依赖与可复用代码缓存分离，恢复/重开按实际上下文还原 |
| 大文件读取边界 | GUI 快速读取先整体读取文件，之后才检查 16 MiB 限制 | 改用检查文件大小且有读取上限的统一入口；拒绝后原状态不变 |
| 非法数值与存档完整性 | `NaN`/`inf` 坐标可进入场景，JSON 会写成不可读的 `null`；异常计数可能 debug 溢出崩溃或 release 回绕 | 坐标/位移入场景前校验有限值，存档前后校验变换和透明度；计数饱和递增，非法保存不覆盖旧文件 |
| 调用深度边界 | 已处于合法 64 层调用时，普通 jump 被误当成新增 call 阻塞 | 仅真正新增调用帧时检查栈上限，跳转与完整返回均有回归 |
| 跨场景残留音效 | 读档只停止登记的循环 SE，旧非循环长音效仍可串音；重开也可能遗留通道或待播放效果 | 全局重开/成功读档产生有序 StopAll，清除旧待播放效果，再恢复新状态需要的声音；失败读档不动旧状态 |
| 坏循环音频重试风暴 | 坏容器/空音频被当作成功登记空 sink，之后每帧重读；重启失败也不退出 | 明确报告坏/空源，失败后移除相应循环，只提示一次，后续显式播放仍可重试；保留正常流式播放 |
| 诊断去重一致性 | 章节检查重启清了场景警告，却未清去重集合，导致保存/恢复后的后续警告不一致 | 新检查上下文重置去重状态，场景状态与快照往返一致 |

其中数值、坏档和 64 层调用问题由合成输入确证，**不代表你的现有存档已损坏或原始剧情已触发这些边界**。

## 实际覆盖

| 模式 | 章节 | 剧情停点 | 表中全部选择分支 | 序列化快照检查点 | 主路径不同图片引用 | 主路径音乐/SE 引用 | 主路径语音引用 | 缺失语音 |

| 基础资源 `--base-only` | 95 | 21,001 | 29 | 95 | 1,969 | 119 | 10,580 | 7 |
| 默认追加资源 | 124 | 28,102 | 31 | 124 | 2,693 | 120 | 14,058 | 0 |

- 两种版本合计 **219 章次、49,103 个停点、60 条分支、219 个序列化检查点**；不是 219 个互不重复的章节。
- 每章从头按默认选择推进到其作者定义的下一章/结束。另逐一走选择表中的所有分支，检查汇合/目标和产生的图片、音乐/音效、语音引用；没有穷举所有选择的笛卡尔组合。
- 每章一个检查点验证 JSON 往返、恢复状态及下一次推进后的状态、变量、位置和音频效果一致，不声称形式化证明全部未来执行。
- 图片和必需音乐/音效引用未发现缺失或歧义。基础模式的 7 条缺失语音按原有策略静默继续；追加模式主路径未发现缺失语音。
- 命名空间内 **227 条 Vorbis 音乐/音效**全部通过读取校验、首样本探测及未连接队列入队；没有创建输出设备进行试听，也没有整曲展开成 PCM。检测空源时不能仅依赖初始 span 长度，本轮正向测试已防止误拒正常曲目。
- 既有 Opus 选样解码、归档边界、损坏校验、缓存回收、头像前景、选择命中、通知过期和旧报错存档恢复测试仍通过。
- 正确性/可疑行为为重点的 Clippy 检查通过。构建中旧 objc 宏的 `unexpected cfg` 警告仍存在，未把它当成功能 bug 或声称全部风格警告清零。

当时的优化版另记录 **13 项**坏档 / 运行时 / 全模式审计回归通过。调试、优化版、原始失败复现和 Clippy 日志都属于本机诊断产物，被版本控制排除，不随公开仓库提供；不再将它们列为可下载链接。下述源测试可用于重新验证现有修复，但当前源码不会再次产生修复前的失败日志。

## 仍有的限制与未验证部分

1. 仍是受限兼容运行时，不是完整原版引擎：**影片播放、复杂动画时序及原版场景回想仍未实现，留待后续工作**；B 仅显示最近 6 条对话历史，不是场景回想。画面震动和原始演出时长等未完整复刻；未知语义仍明确阻塞，不擅自跳过。
2. 没有逐帧、逐场景目视检查所有新增图片/演出，也未做全部图片的像素解码和全部 Opus/整曲试听。因此“引用可解析”不等同于所有画面和声音都已人工验收。
3. 没有完成数小时真实交互、所有窗口尺寸/外接屏/音频设备切换及睡眠唤醒压力测试。现有 Metal 离屏回归与窗口共享编码路径，但不等于每个选项都做了系统鼠标实点。
4. 合成异常输入覆盖常见确定缺陷，不是对所有恶意输入的形式化安全验证；归档身份是索引/大小身份，不是全部 4.9 GB 载荷的密码学认证。
5. 不承诺“零 bug”；新增资源、不同版本或此前未走到的条件仍可能暴露新的兼容边界。

## 本机复现

以下步骤不是普通 CI。仅在合法拥有相应资源、使用已验证的 **Rust 1.95.0、macOS / Apple Silicon** 并具备可用 Metal 设备时自愿执行；不承诺 Intel、iOS 或 Windows 覆盖。先按[构建说明](<../BUILD-AND-RUN.md>)从 GitHub 获取源码并准备 SDK / CMake 环境，在同一终端的项目子目录执行。**完整套件的 UI 回归可能初始化音频设备并走正常播放路径，先将系统音频静音**；不要启用截图输出变量：

```sh
export KOIKARI_GAME_ROOT="/path/to/owned-game"
export KOIKARI_ASSET_ROOT="$KOIKARI_GAME_ROOT"
unset KOIKARI_NOTICE_CAPTURE_DIR KOIKARI_DUMP_IMAGES KOIKARI_WINDOW_SHOT
mkdir -p ../diagnostics

# 当日完整检查的复现入口：需自有资源，Metal 验证显式启用
KOIKARI_METAL_TESTS=1 cargo +1.95.0 test --locked --all-targets -- --nocapture --test-threads=1 \
  > ../diagnostics/comprehensive-audit-after.log 2>&1

# 优化版坏档、运行时及双模式无画面状态审计
cargo +1.95.0 test --release --locked \
  --test audit_save_validation --test audit_runtime_regressions \
  --test full_compatibility_audit -- --nocapture --test-threads=1 \
  > ../diagnostics/comprehensive-release.log 2>&1

cargo +1.95.0 clippy --locked --all-targets \
  > ../diagnostics/comprehensive-clippy.log 2>&1
```

检查每条命令的退出状态及本机日志；当前通过数量可能随源码变化，不能要求与历史总数机械一致。基础模式与追加模式都要覆盖时，所选资源目录须含当时所测的基础、补丁及可选追加归档；缺少追加包时只会审计基础模式。无资源或未启用 Metal 时，部分测试提前返回，不是实际验证成功。

全模式状态测试不输出台词、不渲染图片、不播放媒体；完整套件还包含图片/音频选样解码及 Metal 像素验证，因此不能把完整套件等同于纯合成 CI。日志只在本机生成；不要公开上传游戏内容、原始资源或用户存档。普通 CI 的安全运行方式以[测试说明](<TESTING.md>)为准。
