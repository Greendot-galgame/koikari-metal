# 场景生命周期指令兼容修复

## 问题与处理

新增资源的 `scenario/main/5_3.ks:8` 使用 `SC_SceneStartProcess`，此前没有对应的原生处理器，因此运行时在此阻塞。

已按原宏的普通剧情分支补齐：

- 无参数的场景开始只更新场景标志，不清除既有背景、音乐、立绘或消息框状态。实际追加包中 26 处调用均无参数。
- 提供背景时按原宏的背景切换语义处理；音乐缺省时保留，显式停止时停止；消息框按相应默认样式恢复。
- 普通 `SC_SceneEnd` 只清除场景标志，不擅自跳章、黑场或停止音乐；`SC_EndProcess` 也执行这一步，再沿既有章节表继续。
- 同章后续还会遇到 `whiteout`，现按当前立即转场模型保留它的最终背景，其他图层及音乐不丢失。并未完整还原白闪的原始时长。
- 对于旧版保存的这几条已修复指令的未知指令错误，加载后第一次推进会在**原程序位置重新执行**。必须同时匹配当前指令、位置、行号和原错误，其他未知指令、参数错误、条件错误不会被清除或跳过。

## 如何继续

先退出旧游戏窗口，再用原命令启动新版，F9 读取存档，然后按一次空格/回车或点击推进。如果存档正好停在此次报错位置，会重试该指令，不必手动跳到下一章。

本次没有修改任何原始归档或用户存档，资源模式及默认存档位置也没有变化。

## 验证

**101 项测试全部通过**，见[测试日志](<../../diagnostics/scene-lifecycle-tests.log>)。

- 26 个追加章节初始化点均能到达首个对话停点。
- 报错章节无画面推进 **271 个对话停点**，经过后续白闪指令并到达下一章，结束标志也正常清理。
- 使用真实指令位置构造旧错误存档，验证加载后可继续；合成测试同时验证不会绕过其他真实错误。
- 场景继承、背景/音乐缺省、场景结束、白闪最终状态及存档恢复均有合成回归；既有图层、音频、选项、存档提示和两种资源模式的回归仍通过。

以上新增场景验证仅处理状态，不输出台词、渲染图片或播放媒体；不执行原始 TJS/DLL。

## 兼容边界

这不是对原宏所有功能的完整复刻。原版图库读记录、场景专用音量配置和原版回想导航仍未集成；回想模式会明确阻塞，不会猜测跳转目标。普通剧情的场景状态及章节继续已覆盖本次报错案例。其他未实现的复杂动画/转场时序限制仍然存在。
