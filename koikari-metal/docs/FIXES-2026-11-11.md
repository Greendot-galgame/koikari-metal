## 使用源码更新

公开仓库不提供早期本机交付的可执行文件或备份。请从 [GitHub 源码](<https://github.com/Greendot-galgame/koikari-metal>)构建；已有源码检出在项目子目录执行：

```sh

```

## 修复内容

1. **小头像重叠、被文本框盖住**：头像现在有明确的前景属性，切换人物时只保留一个头像。绘制顺序改为背景 → 普通立绘及表情/配件 → 文本框 → 小头像 → 人名和正文；正文避让头像。隐藏文本或进入选择时同步隐藏头像。读取旧 v1 存档时迁移此前重叠的头像状态。
2. **无脸、黑背景、只剩眼睛/部分配件**：原来的“曾经上传”字典在 Metal 纹理被 LRU 淘汰后仍返回成功，导致后续绘制直接跳过。现在纹理对象、尺寸和驻留状态由同一缓存管理，淘汰后会重新解码上传；文字纹理也一样处理。
3. **同帧复杂组合缺层**：本帧已经使用或新上传的纹理受保护，不会因后续文字/图片上传而丢失。即使单帧工作集超过预算，也先保证该帧完整，之后再回收旧资源。单个顶点缓冲区在 GPU 消费结束前不再被下一帧覆盖。长离屏回放逐帧释放临时 Metal 对象。
4. **部分选项点不到**：绘图和命中检测共享同一套矩形与等比留黑边变换；使用实际窗口物理尺寸，不再以固定 1280×720 换算鼠标位置。Retina drawable 不再重复乘 DPI。选项多时自动缩排，避免后面的项目出屏。
5. **相关组合细节**：立绘身体、表情、腮红和配件共用原点；重复配件不再叠两次，遵循原作部分表情禁用腮红的配置。有限立绘动作读取原始声明中的最终位置，不再把所有动作都当成零位移。

## 重跑验证

下列步骤仅供合法持有资源者在 macOS / Apple Silicon、Rust 1.95.0 和可用 Metal 设备上自愿本机复现；不属于普通 CI。先按[构建说明](<../BUILD-AND-RUN.md>)检出源码、准备 SDK / CMake 环境，在同一终端的项目子目录执行。**完整套件中的 UI 回归可能初始化音频设备并走正常播放路径，先将系统音频静音**；截图仅在下述显式可选步骤生成：

```sh
export KOIKARI_GAME_ROOT="/path/to/owned-game"
export KOIKARI_ASSET_ROOT="$KOIKARI_GAME_ROOT"
unset KOIKARI_NOTICE_CAPTURE_DIR KOIKARI_DUMP_IMAGES KOIKARI_WINDOW_SHOT
mkdir -p ../diagnostics
KOIKARI_METAL_TESTS=1 cargo +1.95.0 test --locked --all-targets -- --nocapture --test-threads=1 \
  > ../diagnostics/final-tests.log 2>&1

# 可选：此步骤会读取并渲染自有资源，输出仅留在本机
cargo +1.95.0 build --release --locked
./target/release/koikari-metal --root "$KOIKARI_GAME_ROOT" \
  --scenario scenario/main/0_2.ks --line 306 \
  --capture-replay --texture-budget-mib 32 --size 1280x720 \
  --capture ../diagnostics/background-replay.png
```

检查每条命令的退出状态与本机日志。诊断目录中的日志和截图被版本控制排除，不要将游戏内容或用户存档上传到公开问题报告。

`--line` 从章节开头执行到指定脚本行或之后首个停点，不会跳过前面的背景/立绘设置；`--choice N` 仅选择第一次遇到的分支的第 N 项（1 开始）。

## 仍然存在的兼容性边界

这是原生重写运行时，不是完整的原版 KiriKiri/TJS 引擎。**影片播放、复杂动画时序及原版场景回想仍未实现，留待后续工作**；B 只显示最近 6 条对话历史。震动、颜色演出、精确过渡时长、延迟表情、循环运动及跨转场的运动时序尚未完整复刻。这些限制不等同于本次已修复的缓存丢图问题，也不能据四个场景的回归推断全部原作演出已完全还原。

游戏资源保持只读，不执行 Windows 程序、Steam 组件或原始 TJS；没有覆盖原版存档。
