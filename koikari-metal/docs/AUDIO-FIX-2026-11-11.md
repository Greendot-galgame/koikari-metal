# 语音加载红条修复（2026-11-11 历史记录）

> 本文保留当时基础资源模式的原因与验证结果，不代表当前测试总数。后续 124 项测试记录见[全面检查](<COMPREHENSIVE-AUDIT-2026-11-11.md>)；现行构建与测试见[构建说明](<../BUILD-AND-RUN.md>)和[测试说明](<TESTING.md>)。真实资源测试不在普通 CI 中，本次文档更新没有运行、展示或播放游戏内容。
>
> 代码采用[根 MIT 许可证](<../../LICENSE>)，图片、游戏截图与原始游戏资源不在代码许可范围内。

## 原因

当时的基础游戏资源索引中不存在 `vo5_1089` 和 `vo5_1169`，但剧情脚本仍引用它们。相邻的 `vo5_1088`、`vo5_1090`、`vo5_1168`、`vo5_1170` 都存在，且当时实际 Opus 解码正常。可选追加包可提供这两条语音，见[追加归档说明](<ADDITIONAL-ARCHIVE.md>)；不能把基础模式的缺失结论推广到其他资源版本。

旧程序把这类缺失当成音频错误写入永久状态，后面即使已经换了台词和场景，红条仍一直显示。它不是游戏剧情被中断，也不是图片资源丢失。

## 处理

- 真正缺失的语音作为无配音台词正常继续，仅在终端记录一次；不再弹红条，也不播放错误的替代语音。
- 先停止上一句语音，避免缺失台词仍残留上一句声音。
- 只有确认不存在才静默跳过。路径不合法、别名歧义、读取失败、校验失败、解码异常仍保留诊断。
- 真实音频问题与脚本/图片等持久错误分开：音频提示最多显示 **4 秒**，推进下一句立即清除；同一停点重复的后台警告不会不断延长提示。
- 终端保留完整错误原因，脚本、图片等真正的持久故障不会被这个超时机制隐藏。

**无法凭空恢复基础资源包没有的录音，因此仅使用基础资源时这两句仍然无声。** 其他已有语音照常播放；可选追加包的情况见上文说明。修复没有修改原始游戏资源或存档。

## 验证

**该阶段历史记录为 79 项测试全部通过**，不是当前测试数量。诊断日志只在本机复现时生成，被版本控制排除，不随公开仓库分发。源回归位于[音频内部测试](<../src/audio.rs>)、[界面内部测试](<../src/main.rs>)和[基础资源运行时测试](<../tests/runtime_game.rs>)。

验证包含：

1. 从真实章节执行到两条缺失语音，调用正常界面的 `Player.apply_effects`，确认没有红条状态且能继续下一句。这次不是仅用会跳过音频的截图模式验证。
2. 对相邻四条现存语音实际解码为非空 PCM，确保没有用“全局禁用语音”掩盖问题。
3. 使用合成归档确认缺失与校验错误、歧义、非法路径严格区分。
4. 用可控时钟测试 4 秒消失、下一句清除、重复提示不续期及持久错误优先级；原有图层和选项测试仍全部通过。

实现：[资源可选查询](<../src/assets.rs>)、[语音处理](<../src/audio.rs>)、[限时提示](<../src/transient_notice.rs>)、[界面效果处理](<../src/main.rs>)。

## 本机复现与源码更新

先按[构建说明](<../BUILD-AND-RUN.md>)从 GitHub 检出源码、准备 SDK / CMake 环境，推荐使用已验证的 Rust 1.95.0、macOS / Apple Silicon。只有合法持有资源且明确选择本机资源 / Metal 验证时，才在同一终端的项目子目录执行。**完整套件的 UI 回归可能初始化音频设备并走正常播放路径，先将系统音频静音**；不要启用截图输出变量：

```sh
export KOIKARI_GAME_ROOT="/path/to/owned-game"
export KOIKARI_ASSET_ROOT="$KOIKARI_GAME_ROOT"
unset KOIKARI_NOTICE_CAPTURE_DIR KOIKARI_DUMP_IMAGES KOIKARI_WINDOW_SHOT
mkdir -p ../diagnostics
KOIKARI_METAL_TESTS=1 cargo +1.95.0 test --locked --all-targets -- --nocapture --test-threads=1 \
  > ../diagnostics/audio-fix-tests.log 2>&1
```

检查命令退出状态和本机日志；没有资源或未启用 Metal 时，部分测试提前返回，不能据测试数量推断已复现音频或界面回归。不要上传原始语音、剧情或用户存档。

公开仓库不提供预编译可执行文件。更新源码并完全退出旧游戏窗口后，自行构建再启动：

```sh
cargo +1.95.0 build --release --locked
./target/release/koikari-metal --root "$KOIKARI_GAME_ROOT"
```

此修复不新增演出能力：影片、复杂动画时序、原版场景回想仍未实现，留待后续工作；B 仅为对话历史。
